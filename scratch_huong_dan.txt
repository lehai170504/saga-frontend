# SAGA FRONTEND INTEGRATION HANDOFF — CURRENT MAIN

## 0. Auth chung — cực kỳ quan trọng

Backend SAGA dùng **Spring Security session**, không dùng Bearer cho browser business API.

```ts
fetch(url, {
  credentials: "include",
});
```

Quy tắc:

```text
GET
→ credentials: include
→ không CSRF

POST / PUT / PATCH / DELETE
→ credentials: include
→ phải gửi CSRF

Authorization: Bearer ...
→ KHÔNG dùng cho SAGA browser API
```

Lấy CSRF trước mutation:

```ts
async function getCsrf() {
  const res = await fetch("/api/auth/csrf", {
    credentials: "include",
  });

  if (!res.ok) throw new Error("Không lấy được CSRF");

  return res.json();
}
```

Ví dụ mutation:

```ts
async function putJson(path: string, body: unknown) {
  const csrf = await getCsrf();

  const res = await fetch(path, {
    method: "PUT",
    credentials: "include",
    headers: {
      "Content-Type": "application/json",
      [csrf.headerName]: csrf.token,
    },
    body: JSON.stringify(body),
  });

  if (!res.ok) {
    throw await res.json();
  }

  return res.json();
}
```

Browser chỉ nói chuyện với **SAGA Backend**. Đặc biệt với AI, FE không được giữ AI service token/provider key hay gọi service AI trực tiếp.

# 1. Avatar Google / Cognito

## API FE dùng

```http
GET /api/auth/me
```

Response hiện có thêm:

```json
{
  "avatarUrl": "https://..."
}
```

`avatarUrl` có thể `null`.

### FE rendering

```tsx
<img
  src={user.avatarUrl ?? "/images/default-avatar.png"}
  alt={user.fullName}
/>
```

### FE không cần làm

```text
❌ Không gọi Google API lấy avatar
❌ Không lấy Google access token
❌ Không gửi picture URL về Backend
❌ Không dùng Bearer
```

Backend tự đồng bộ standard OIDC claim:

```text
Google picture
→ Cognito picture
→ Backend login
→ avatar_url
→ /api/auth/me.avatarUrl
```

Cấu hình Google → Cognito `picture` đã được xác nhận ở console; **runtime logout/login Google → `/api/auth/me.avatarUrl` vẫn cần smoke trước khi gọi production-confirmed**.

# 2. Admin Dashboard V1

## 2.1 Anomaly Report

```http
GET /api/admin/reports/anomalies
```

Role:

```text
ADMIN       → 200
LECTURER    → 403
STUDENT     → 403
Anonymous   → 401
```

GET nên:

```ts
fetch("/api/admin/reports/anomalies", {
  credentials: "include",
});
```

Semantics hiện tại:

```text
OVERDUE_TASK
→ SUPPORTED
→ count thật

MSR
→ TBD
→ count = null

DEADLINE_PROCESS
→ TBD
→ count = null

SNA_ISOLATION
→ TBD
→ count = null
```

FE **không được biến `null` thành `0`**. Admin Dashboard contract xác nhận chỉ OVERDUE_TASK có source thật; các signal còn lại phải hiển thị trạng thái chưa hỗ trợ. 

Ví dụ:

```tsx
if (signal.supportStatus === "TBD") {
  return <span>Chưa hỗ trợ</span>;
}

return <span>{signal.count}</span>;
```

Đây là feature mình vừa thêm.

## GET current Course weights

```http

```

Role hiện hành:

```text
ADMIN
→ read được

LECTURER
→ chỉ Course mình giảng dạy

STUDENT
→ không dùng màn này
```

GET không CSRF.

---

## PUT Course weights

```http
PUT /api/v1/courses/{courseId}/contribution-slice-weights
```

Role:

```text
LECTURER exact Course instructor → success

LECTURER Course khác → 403

ADMIN → 403 cho direct PUT hiện tại

STUDENT → 403
```

Cần CSRF.

Actor được Backend lấy từ:

```text
SagaPrincipal.localProfileId
```

FE **không gửi**:

```json
{
  "lecturerId": "...",
  "adminId": "..."
}
```

### Body

Course weights dùng **0..100**:

```json
{
  "codeWeight": 30,
  "documentWeight": 20,
  "designWeight": 50
}
```

Validation:

```text
mỗi weight >= 0

code + document + design
≈ 100

tolerance ±0.01
```

### Đừng nhầm hai weight system

```text
PROJECT GROUP WEIGHT
PUT /api/projects/{projectId}/group-weights

0.4 + 0.3 + 0.3 = 1.0
```

còn:

```text
COURSE SLICE WEIGHT
PUT /api/v1/courses/{courseId}/contribution-slice-weights

40 + 30 + 30 = 100
```

### Contribution precedence

Backend tính theo:

```text
Có Project+Team GroupWeight?
          │
        YES
          ↓
dùng Project GroupWeight

          │ NO
          ↓
dùng Course Weight Lecturer cấu hình
```

Không đổi Contribution formula, Peer Review hay Rubric.

---

## Flow cũ Lecturer request → Admin approve

Các API cũ hiện vẫn tồn tại để backward compatibility:

```http
POST /api/v1/courses/{courseId}/contribution-slice-weight-requests

GET /api/v1/courses/contribution-slice-weight-requests

PUT /api/v1/courses/contribution-slice-weight-requests/{requestId}/decision
```

Nhưng với **FE mới**:

```text

```

Không dùng chúng cho màn Lecturer chỉnh trọng số bình thường.

Official FE flow mới:

```text

       ↓

```

Flow cũ trước đây thật sự là request/Admin decision, nên giữ nó trong Backend không đồng nghĩa FE mới phải tiếp tục dùng.

# 8. Student Progress — MEMBER và LEADER

API:

```http
GET /api/v1/courses/{courseId}/students/{studentId}/progress
```

Không CSRF.

### MEMBER

```text
xem chính mình
→ 200

xem teammate
→ 403
```

### LEADER

```text
xem chính mình
→ 200

xem thành viên exact same Team
→ 200

Team khác
→ 403

Course khác
→ 403
```

### MENTOR

```text
403
```

Legacy ambiguous membership:

```text
nhiều Team trong cùng Course
→ 409
→ Backend fail closed
```

Không pick Team đầu tiên.

### FE rendering

Nếu user là MEMBER:

```ts
GET /api/v1/courses/${courseId}/students/${me.localProfileId}/progress
```

Nếu user là LEADER và chọn một teammate:

```ts
GET /api/v1/courses/${courseId}/students/${studentId}/progress
```

**Không gửi role hoặc caller ID trong request.**

Backend tự lấy actor từ session.

### Không suy rộng quyền Student

Feature mới này chỉ mở:

```text
/progress
```

Không có nghĩa Student được gọi luôn:

```text
❌ Lecturer Dashboard
❌ Lecturer early-warning
❌ Lecturer contribution-detail
❌ Lecturer activities
```

# 10. AI Task Proposal không tự mutate Jira

Đây là điểm FE phải hiểu đúng.

User chat:

```text
"Tạo task Fix login bug"
```

AI có thể tạo:

```text
pending action
```

Nhưng lúc đó:

```text
Jira chưa bị sửa
```

FE render:

```text
[Confirm]
[Reject]
```

### Confirm

```http
POST /api/v1/ai/pending-actions/{actionId}/confirm
```

Cần CSRF.

Flow:

```text
FE confirm
→ Backend reauthorize user
→ JiraTaskWriteService
→ Jira mutation
→ canonical result
```

### Reject

```http
POST /api/v1/ai/pending-actions/{actionId}/reject
```

Cần CSRF.

```text
reject
→ không Jira call
```

Task create/update của AI là **two-phase**, không auto mutation.

# 11. AI Artifact / SRS

Download:

```http
GET /api/v1/ai/artifacts/{artifactId}/download
```

Không CSRF.

Frontend nên tải như blob:

```ts
const res = await fetch(
  `/api/v1/ai/artifacts/${artifactId}/download`,
  {
    credentials: "include",
  }
);

const blob = await res.blob();

const url = URL.createObjectURL(blob);
const a = document.createElement("a");
a.href = url;
a.download = "saga-srs.docx";
a.click();

URL.revokeObjectURL(url);
```

Không gọi AI service hoặc HF URL trực tiếp.

AI canonical SRS nằm trong AI durable state; Backend kiểm authorization lại trước download.

# 13. Error handling chung cho FE

```text
400
→ validation/request sai
→ show lỗi
→ không retry mù

401
→ session expired/not login
→ redirect login

403
→ role/ownership sai hoặc mutation thiếu CSRF
→ không đổi role bằng FE

404
→ resource không tồn tại / không thuộc scope

409
→ business conflict
→ hiển thị conflict
→ không tự chọn dữ liệu khác để workaround

5xx
→ Backend/provider unavailable
→ show retry state phù hợp
```

Đặc biệt:

```text
403 không có nghĩa "thử Bearer token"
```

Không bao giờ fallback sang Bearer.
